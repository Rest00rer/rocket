# Спецификация тестового CheckStock

## 1. Цель

Менеджер должен сразу видеть, где находится каждый товар:

- физически на конкретном ФФ;
- доступен для новых операций;
- зарезервирован под FBS;
- перемещается между ФФ;
- едет клиенту по FBS;
- едет на склад маркетплейса по FBO.

## 2. Тестовые данные

Один магазин, два активных ФФ: `Север` и `Юг`.

| SKU     | Товар       | Север | Юг |
| ------- | ----------- | ----: | --: |
| SKU-101 | Органайзер  |    10 |   6 |
| SKU-102 | Контейнер   |     5 |   0 |
| SKU-103 | Корзина     |     0 |   4 |

Seed должен быть повторяемым и не создавать дубли при повторном запуске.

## 3. Экран остатков

Для каждой пары товар/ФФ показываются:

- физический остаток `on_hand`;
- резерв FBS `reserved_fbs`;
- доступно `available = on_hand - reserved_fbs`;
- признак архивного ФФ.

Отдельными итогами показываются количества в пути: между ФФ, по FBO и к
клиенту по FBS. Нельзя суммировать одно и то же физическое количество дважды.

## 4. Склады

Пользователь может добавить, переименовать и удалить ФФ.

Удаление означает архивирование:

- остатки не переносятся и не обнуляются автоматически;
- история сохраняет название и ссылку на склад;
- склад и его остатки остаются видимыми с отметкой «архивный»;
- новые приходы, резервы и отправки с него запрещены;
- разрешено переместить оставшийся товар из архивного склада в активный.

## 5. Приход

Приход увеличивает `on_hand` выбранного товара на выбранном активном ФФ и
добавляет одну запись в историю.

## 6. Перемещение между ФФ

1. Создаётся черновик перемещения.
2. При отправке проверяется доступность товара на source ФФ.
3. Успешная отправка уменьшает `on_hand` source и переводит перемещение в
   `in_transit`.
4. Приёмка увеличивает `on_hand` destination и переводит его в `received`.
5. Повторная отправка или приёмка не меняет остатки повторно.

## 7. FBS

### Резерв

Резерв возможен только в пределах `available` выбранного ФФ и увеличивает
`reserved_fbs`.

### Отмена

Отмена зарезервированного заказа уменьшает `reserved_fbs`, не меняя `on_hand`.

### Отправка клиенту

Отправка зарезервированного заказа одновременно уменьшает `reserved_fbs` и
`on_hand`. Количество после этого показывается в блоке «В пути к клиенту».

## 8. FBO

Создание FBO-отправки проверяет `available` выбранного ФФ, уменьшает его
`on_hand` и создаёт отправку `in_transit`. После подтверждения приёмки статус
становится `received`; повторная приёмка не меняет состояние.

## 9. Нехватка на выбранном ФФ

Система не списывает товар с другого ФФ автоматически. Если на выбранном складе
недостаточно, команда возвращает `409 insufficient_stock` с полями:

```json
{
  "code": "insufficient_stock",
  "message": "На складе Север доступно 2 из 5 единиц",
  "details": {
    "requested": 5,
    "available_here": 2,
    "available_total": 8,
    "alternatives": [{"warehouse_id": "...", "name": "Юг", "available": 6}]
  }
}
```

Интерфейс показывает эту информацию и предлагает выбрать другой ФФ или создать
перемещение, но не делает этого без подтверждения пользователя.

## 10. Идемпотентность

Команды отправки, приёмки, резерва, отмены и прихода принимают заголовок
`Idempotency-Key`.

- первый запрос выполняет операцию и сохраняет ответ;
- точный повтор возвращает тот же ответ без новых списаний;
- повтор ключа с другим телом возвращает `409 idempotency_conflict`.

## 11. История

История отсортирована от новых операций к старым и содержит:

- тип действия;
- SKU и название товара;
- количество;
- откуда и куда;
- статус/результат;
- дату и время.

Фильтры: SKU, склад и тип операции.

## 12. Ошибки и состояния UI

- loading при загрузке и выполнении команды;
- empty для пустого списка;
- понятная inline-ошибка формы;
- retry для сетевой ошибки;
- кнопка подтверждения блокируется во время запроса;
- успешная команда обновляет остатки и историю.

## 13. API

Предварительные контракты находятся в `docs/api.md`. Все ошибки используют
единый формат `{code, message, details, request_id}`.

## 14. Обязательные тесты

1. Seed создаёт заданные остатки без дублей.
2. Приход увеличивает физический остаток.
3. FBS-резерв уменьшает available, но не on_hand.
4. Отмена возвращает резерв.
5. FBS-отправка уменьшает on_hand и резерв.
6. FBO-отправка уменьшает on_hand и появляется в пути.
7. Отправка и приёмка перемещения сходятся по остаткам.
8. Нехватка выбранного ФФ не списывает товар с другого склада.
9. Архивирование склада сохраняет остаток и историю.
10. Повтор подтверждения с тем же ключом ничего не списывает дважды.
11. Параллельные списания не создают отрицательный остаток.

## 15. Критерии готовности

- проект запускается одной командой по README;
- основной сквозной сценарий работает в интерфейсе;
- все обязательные сценарии покрыты тестами;
- после каждой операции сходятся остатки и количества в пути;
- нет шаблонных страниц и неиспользуемых зависимостей;
- README объясняет решения и компромиссы, а не только перечисляет функции;
- видео 3–5 минут показывает сквозной сценарий, нехватку, удаление ФФ и
  повторное подтверждение.

## 16. Вне границ тестового

Реальные API маркетплейсов, прогнозы, закупочная потребность, кабинеты WB,
авторизация, фоновые задачи и production-инфраструктура относятся к проекту
Raketa и не реализуются в CheckStock.
